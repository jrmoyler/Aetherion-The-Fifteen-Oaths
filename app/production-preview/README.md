# Production asset workshop

An isolated Three.js GLB inspection app. Existing ability code is unchanged. The link opens the existing sandbox separately; this viewer does not integrate weapons into gameplay or certify matching appearance.

From this directory, run `npm ci`, `npm test`, `npm run dev`. Open the Vite URL (default port 5174). Run the ability app separately from the repository root with `npm run dev:abilities` for the port-5173 link. `npm run build` produces the standalone `dist/` directory; `npm run preview` serves that build. `npm run test:http` exercises the development server and verifies every currently discoverable GLB/LOD against its source bytes. Missing manifests produce an explicit empty state, not substitute models.

The server recursively discovers `assets/production/**/manifest.json` without a fixed Oath/family list. Each manifest contains `assets[]` with `id`, `name`, `status` and `files.glb`, optional `files.lod1` and `files.lod2`. Artist file paths are repository-relative under `assets/production/`. Build copies only discovered manifests, the GLB states/LODs this viewer uses, and image/buffer dependencies actually referenced by those GLBs. DCC sources, documents, unused render/texture files and unused collision exports are neither copied nor served. The resulting app has no dependency on executor filesystem URLs. Rebuild after exports change.

Controls inspect authored LODs, animation/rest pose, textured PBR, untextured PBR, surface normals and wireframe. The camera fits world-space bounds; geometry is not recentered or rescaled. Neutral hemisphere/directional illumination and ground are inspection lighting, not an approved scene environment. PBR means glTF materials are rendered by Three's standard glTF pipeline; the UI does not certify texture packing or visual quality.

Optional `files.damaged` and `files.stowed` appear in the state selector as separate exports with LOD 0 only. They never inherit ready-state LODs; choosing a state resets detail level and disables the LOD selector when only one export exists. Separately manifested entries with `variant` retain their original IDs, variant labels and their own authored LODs. These remain distinct records; the UI does not invent archetype grouping. Optional `archetypeId` is displayed if provided.

Ownership tests exercise cancelled/late loads, replacement, mixer cleanup, shared resource deduplication and rejected loads. Fetch uses cancellation; a late GLTF parse is discarded and disposed. Active mixers stop and uncache their scene, textures/materials/geometries/skeletons and decoded ImageBitmaps are released, and temporary material views restore originals before disposal. The viewer caps pixel ratio at 2; this is a proposed operational choice, not a measured performance budget.

Browser rendering and appearance require a real browser run. Node tests, HTTP checks and a successful build do not establish WebGL rendering, shader acceptance, visual parity, animation correctness, gameplay, Unreal/Godot compatibility or art approval. No browser sandbox flags are changed by this app.

`npm run test:assets -- /tmp/asset-import-report.json` loads every current manifested LOD through the actual Three.js GLTFLoader, checks finite geometry/material values, samples animation transforms and verifies geometry/material disposal events. Node lacks browser image decoding: loader image warnings are retained and texture decode is explicitly unverified. `npm run test:http:build` checks the built preview and byte-compares all copied GLBs to their current source files; rebuild before running it if assets changed.

The canvas supports focused keyboard orbit (arrow keys), zoom (+/−), and fit (F/Home). Tab leaves the view; inspection controls gate camera input. Animation/material and long help notes start collapsed. Reduced-motion preference disables camera damping and starts clips paused, with explicit Play opt-in. Context loss pauses rendering and requests browser recovery; restored contexts resume the same CPU scene. Unsupported or failed renderers keep a readable DOM fallback and retry action. Hidden tabs and BFCache navigation suspend rendering without destroying a restorable scene.

[Game Studio audit and browser playtest gates](PLAYTEST.md) separates implemented/tested logic from the mandatory screenshots still blocked by the executor's browser sandbox. A successful Node or HTTP test does not waive that gate.

## Reference comparison

The reference panel displays original image bytes in a DOM image, separate from the real 3D scene. Asset and family `referenceIds` resolve through the canon reference index. Only those indexed original images enter the runtime allowlist; unreferenced images and DCC files stay inaccessible. Unresolved IDs fail the build rather than displaying an unrelated reference.

Choose world +Z, +X, −Z or three-quarter orthographic views, or perspective. XYZ view rotation aligns differing authoring axes and resets on asset selection; it does not modify mesh coordinates or source files. Vertical framing and target-height offset use meters. Fit uses actual world bounds. Silhouette, wireframe and PBR modes support shape and material comparison. References carry no inferred physical scale or automatic approval.

Browser screenshots and rendered comparison remain an unexecuted acceptance gate in this environment. CPU camera, correspondence, image replacement, allowlist and original-byte HTTP tests do not establish visual fidelity.

## Opt-in published review revisions

Run `AETHERION_INCLUDE_REVIEWS=1 npm run dev` from this directory to add the published review entries: Kiln ninja V10/V15/V16, Fault blade V11/V13, Impulse shield V8b and the 17 Daybreak r05 modules. Select names beginning `[Review]` in the asset menu. The same flag works with `npm run build`, `npm run test:assets`, `npm run test:http` and `npm run test:http:build`; rebuild before switching built modes. The default catalog and production acceptance counts are unchanged.

The opt-in catalog preserves Ninja V10 from revision 06, Fault blade V11 from revision 05, and Impulse shield V8b from revision 04. Revision 08 adds the Ninja V15 walk-grounding candidate, Fault V13 and Daybreak r05. Revision 09 appends the Ninja V16 left-bracer candidate with the prior review entries retained. Ninja V14 material diagnostics, earlier Daybreak r04 and baseline exports remain offline evidence. All entries are explicitly unapproved candidates; engine checks do not certify the repaired walk, socket interfaces or reference likeness.

The opt-in catalog pins 63 visual GLBs by SHA-256: the original five plus three Ninja V15 LODs, one Fault V13 export, 51 Daybreak r05 LODs and three Ninja V16 LODs. This represents 23 review entries; repeated LODs and revisions are not new completed designs. With the frozen 209-export production catalog, the combined expected count is 272 visual GLBs. The default catalog remains separate and still loads the existing production Daybreak r03 bytes. It exposes no review Blender sources, collision hulls, documents or unused maps. External GLB dependencies, changed bytes at catalog collection, escaping paths and unavailable original-reference IDs fail closed. The development server serves immutable verified review buffers, so later on-disk replacements cannot substitute unpinned bytes; restart after an intentional pinned-manifest update. The models use the existing real GLTFLoader, animation/LOD/material controls and disposal lifecycle. Daybreak review IDs use their own namespace and retain the authored artifact IDs as metadata. This browser inspector loads visual geometry only: it does not instantiate Daybreak movement proxies or provide baffle collision authority. The only reference images are the existing indexed originals; reference imagery is never used as mesh geometry.

These remain unapproved review revisions. CPU import/material-value/animation/disposal and exact-byte HTTP checks do not establish browser texture decoding or GPU appearance. The new review catalog does not certify a match between Blender, Three.js, Godot or Unreal rendering.
